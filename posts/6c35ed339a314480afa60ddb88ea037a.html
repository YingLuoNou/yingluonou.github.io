从0构建hackCPU:一、从零开始

#前言

从身边的洗衣机、冰箱，到我们每天使用的手机、电脑，几乎每一台现代电子设备中，都存在着一个负责控制和运算的“大脑”——中央处理器（CPU）。它执行一条条指令，处理数据、控制外设，并驱动整个系统按照既定的逻辑 运行。可以说，CPU 已经深入现代电子世界的每一个角落。

然而，随着计算机技术不断发展，我们与计算机底层之间的距离似乎也越来越远。

今天，我们可以使用高级语言快速编写程序，调用各种成熟的库和框架，只需要几行代码，就能完成过去需要大量底层工作才能实现的功能。操作系统、编译器、驱动程序以及各种软件框架，为我们构建起了一层又一层的抽象。它们让计算机变得越来越容易使用，却也在无形中将计算机最基础的工作原理隐藏了起来。

我们可以编写程序，却未必知道一行代码最终是怎样变成 CPU 能够执行的指令；可以点击“运行”，却未必真正理解程序为什么需要编译；可以熟练地调用各种函数和接口，却很少有机会看到这些抽象层之下，一条最基本的机器指令究竟是怎样被硬件执行的。

现代 CPU 已经复杂到了惊人的程度。数十亿甚至上百亿个晶体管、流水线、缓存、分支预测、乱序执行……这些复杂的技术很容易让人产生一种感觉：CPU 似乎是一个遥不可及的黑盒，想要真正理解它，就必须掌握大量复杂的知识。

但随着对计算机组成原理和数字电路的进一步学习，我逐渐发现了一件很有意思的事情：

如果暂时抛开现代处理器中那些为了性能而设计的复杂结构，仅仅实现一台能够完整执行程序的简单计算机，那么事情似乎并没有想象中那么困难。

寄存器可以由触发器构成，加法器可以由基本逻辑门搭建，算术逻辑单元可以由组合逻辑实现，程序计数器负责寻找下一条指令，而控制逻辑则决定数据应该在什么时候、流向哪里。

当这些看似简单的模块组合在一起时，一台真正能够执行程序的计算机便逐渐诞生了。

于是，在查阅了大量资料之后，我产生了一个想法：

既然 CPU 的基本原理可以由这些最基础的数字逻辑构成，那么为什么不真正做一台出来？

相比于直接在 FPGA 中描述一个 CPU，我更希望能够真正看到信号在线路之间流动，看到寄存器保存数据，看到程序计数器不断递增，甚至能够拿着示波器或逻辑分析仪去观察每一个时钟周期中究竟发生了什么。

因此，我决定以《The Elements of Computing Systems》（Nand2Tetris）中的 Hack 计算机架构为基础，使用 74 系列数字逻辑芯片，从基本逻辑电路开始，在现实硬件中实现一台属于自己的 Hack CPU。

它不会拥有现代处理器惊人的性能，也不会拥有复杂的流水线和缓存结构。

但它将是一台真正存在于电路板上的计算机。

每一条指令、每一次加法、每一次跳转，最终都能够对应到一组真实变化的电平。

这个博客系列，将记录它从一堆逻辑门，逐渐变成一台能够真正运行程序的计算机的全过程。

#CPU的基本框架

我选择了 Nand2Tetris 中的 Hack 计算机架构，作为这台 CPU 的整体设计基础。Hack 架构非常简洁，没有现代处理器中复杂的流水线、缓存和乱序执行等结构，因此十分适合用基础数字逻辑芯片进行实际搭建。

整个 Hack 计算机主要由 ALU、A/D 两个寄存器、程序计数器（PC，Program Counter）、指令译码与控制逻辑、数据内存（RAM）以及指令内存（ROM） 组成。

其中，ALU（Arithmetic Logic Unit，算术逻辑单元） 可以看作整个 CPU 的“计算核心”，负责完成加法、逻辑与、逻辑或、取反等基本运算。CPU 所执行的大部分数据处理工作，最终都会落实到 ALU 中完成。

与 ALU 直接配合的是 A 寄存器和 D 寄存器。如果把 ALU 比作一张进行计算的桌子，那么寄存器就像放在手边的两张小草稿纸，用来暂时保存当前正在处理的数据。相比之下，数据内存 RAM则像一本更大的草稿本，可以保存程序运行过程中需要长期或大量使用的数据。

指令内存 ROM负责存放程序本身，也就是 CPU 接下来需要执行的一条条机器指令。而 程序计数器 PC 决定 CPU 接下来要从指令内存的哪个位置读取指令，可以将它理解为程序运行时的“书签”：每执行完一条指令，PC 通常会指向下一条指令；遇到跳转指令时，它也可以直接跳到新的位置。

最后，指令译码与控制逻辑负责理解当前指令的含义，并生成相应的控制信号。例如，它会决定 ALU 应该执行什么运算、哪个寄存器需要写入数据，以及程序计数器是继续向下执行还是跳转到其他地址。

这些模块本身都不算复杂，但当它们按照特定的规则连接起来，并在时钟信号的驱动下不断重复“取指令 → 译码 → 运算 → 保存结果 → 执行下一条指令”这一过程时，一个最基本的 CPU 也就开始真正运行起来了。

#软件仿真

在真正开始购买元件、绘制 PCB 之前，软件仿真几乎是必不可少的一步。

毕竟谁也不想兴致勃勃地买完一大堆芯片、画完原理图、打完 PCB，焊接完成后才发现——某根线接错了，或者某一处逻辑设计从一开始就有问题。最后只能修改设计、重新打板，然后再等上好几天。

对于这样一台完全由数字逻辑电路搭建的 CPU 来说，提前在软件中把整个系统“跑起来”，显然要划算得多。

这里我选择使用开源数字逻辑仿真软件 Digital：

Digital 开源项目

Digital 基于 Java 运行，因此需要提前安装合适的 Java/JDK 运行环境。这里给出 Oracle JDK 的下载地址作为参考：

Java Downloads | Oracle

我选择 Digital，最主要的原因是它非常适合这种从逻辑门逐步搭建 CPU 的项目。

它提供了直观的图形化电路编辑界面，可以像画原理图一样直接放置逻辑门、寄存器、多路选择器等元件，再通过导线将它们连接起来。完成电路之后，不需要额外进行编译或综合，就可以直接开始仿真。

在仿真过程中，还可以非常直观地观察各个节点的逻辑电平和数据变化。比如 ALU 当前输出了什么结果、寄存器中保存了什么数据、程序计数器跳到了哪个地址，都可以直接观察。这对于排查 CPU 中的数据通路和控制逻辑问题非常方便。

除此之外，Digital 还有一个对这个项目而言非常重要的优点：它内置了不少 74 系列数字逻辑芯片的仿真模型。

这意味着在前期，我可以先使用普通逻辑门验证 CPU 的整体结构和工作原理；等逻辑确认无误之后，再逐步将这些抽象的逻辑门替换成实际准备使用的 74 系列芯片。

这样一来，软件中的电路就能够逐渐向最终的实物电路靠拢。

最终，我希望做到的是：

先让 CPU 在 Digital 中正确运行，再让同样的逻辑在真实的 74 系列芯片和 PCB 上运行起来。

软件仿真解决的是“这个设计在逻辑上能不能工作”，而之后的实物制作，则要解决“怎样让这些逻辑真正变成桌面上一块会运行程序的电路板”。

接下来，就从 CPU 中最核心的计算单元——ALU 开始，一步步将 Hack CPU 从架构图变成真正可以运行的数字逻辑电路。
